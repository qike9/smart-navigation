## 统一的移动规则与代价模型

八种算法都跑在同一个 `GridMap` 上，规则完全一致，这样比较才有意义：

| 规则 | 说明 | 实现 |
| --- | --- | --- |
| 邻域 | 八方向（可关闭斜向变成四方向） | `GridMap.get_neighbors` |
| 代价 | 直走 1.0，斜走 1.414（≈√2） | `GridMap.get_movement_cost` |
| 禁止穿墙角 | 斜向移动要求两侧正交格都可通行 | `GridMap.get_neighbors` |
| 起终点可为障碍物以外任意格 | 越界/障碍视为不可通行 | `GridMap.is_walkable` |

启发函数统一用**八向距离（octile）**：

```python
h = (dx + dy) + (√2 - 2) * min(dx, dy)
```

它等于在无遮挡地图上从当前点到终点的真实最短距离，因此**可采纳（admissible）**且一致
（consistent）——这是 A\* 与 Theta\* 能保证最优的前提。四向模式下降级为曼哈顿距离。

每个算法都返回统一的 `PathResult`：

```python
result.success          # 是否找到路径
result.path             # List[Position]，含起点与终点
result.path_length      # 路径总代价
result.nodes_explored   # 扩展节点数
result.visited_nodes    # 按扩展顺序记录的节点，用于动画回放
result.execution_time   # 墙钟耗时（秒）
```

## 1. A\*

`AStarAlgorithm` · 保证加权最短 · 默认首选

用 `f = g + h` 排序开放集：`g` 是已走代价，`h` 是到终点的估计剩余代价。由于 `h` 可采纳，
第一次弹出终点时得到的路径就是最优解。

```python
open_set = [start_node]                      # 优先队列，按 f 升序
while open_set:
    current = heappop(open_set)
    if current.position == end: break        # 首次弹出终点即最优
    for neighbor in grid.get_neighbors(current.position, allow_diagonal):
        tentative_g = current.g_cost + grid.get_movement_cost(current.position, neighbor)
        if tentative_g < nodes[neighbor].g_cost:   # 松弛
            nodes[neighbor].g_cost = tentative_g
            nodes[neighbor].parent = current
            heappush(open_set, nodes[neighbor])
```

- **复杂度**：时间/空间 `O(b^d)`，实践中远低于 Dijkstra
- **优点**：最优 + 高效，绝大多数场景的默认选择
- **缺点**：`h` 越接近 0 越退化成 Dijkstra；内存随扩展节点线性增长

## 2. Dijkstra

`DijkstraAlgorithm` · 保证加权最短 · 对照基准

A\* 令 `h ≡ 0` 的特例：只按 `g` 排序，从起点向外"等代价"均匀扩张。它不需要任何启发信息，
因此对代价函数的形式没有假设，是衡量其它算法是否最优的基准线。

- **复杂度**：`O(E log V)`（二叉堆）
- **优点**：绝对可靠，任意非负权重都适用
- **缺点**：没有方向感，向四周铺满，同图上节点数约为 A\* 的数倍

## 3. BFS 广度优先搜索

`BFSAlgorithm` · 保证步数最少

分层推进的队列搜索，先访问所有距离为 1 的节点，再是距离 2……在**无权图**中第一次到达
终点时的步数最少。

- **复杂度**：`O(V + E)`
- **优点**：实现极简，无权场景最短步数有保证；不需要堆，比 A\* 快得多
- **缺点**：看不见代价差异。本项目斜走代价 1.414 ≠ 1，所以 BFS 只保证"步数最少"，
  总长度可能略大于 A\*（实测 84.53 vs 83.70）

## 4. DFS 深度优先搜索

`DFSAlgorithm` · 不保证最短

用栈一条道走到黑，撞墙才回退。

- **复杂度**：`O(V + E)`
- **优点**：内存占用小，找"任意一条路"很快（迷宫求解常用）
- **缺点**：路径极其冗长（实测长度是 A\* 的近 3 倍），且完全看邻居顺序的脸色

## 5. Greedy Best-First 贪心最佳优先

`GreedyBestFirstAlgorithm` · 不保证最短 · 最快

只按 `h` 排序，完全忽略已走代价，永远朝"看起来离终点最近"的方向冲。

- **复杂度**：同 A\*，但常数小、扩展少
- **优点**：实测扩张节点数最少（51×51 稠密图仅 84 个，是 A\* 的 1/22），毫秒级出结果
- **缺点**：会被凹形障碍骗进死路，路径明显绕远（85.11 vs 83.70），不保证最优

## 6. 双向 BFS

`BidirectionalBFSAlgorithm` · 保证步数最少

起点与终点各起一个波前，**逐层交替扩张**，两波相遇即得路径。因为两边各走一半，
搜索规模从 `b^d` 降到约 `2 · b^(d/2)`。

实现要点：每轮完整展开"较浅"一侧的一整层，才能保证相遇时的步数最优（若按单节点交替
弹出，遇到的重叠点不一定最浅，这是这类实现最常见的坑）。

- **复杂度**：`O(b^(d/2))`
- **优点**：大地图上节点数明显少于单向 BFS（3600 → 1922）
- **缺点**：继承 BFS 的"只数步数"局限；要维护两张父指针表

## 7. Jump Point Search 跳点搜索

`JumpPointSearchAlgorithm` · 保证加权最短 · 开阔地形神器

JPS 是 A\* 的剪枝变体。核心洞察：在空旷区域里，绝大多数格子是对称冗余的——你完全不必
逐格扩展，只需沿直线/对角线"跳"到下一个**必须做决策的点**（跳点）：

1. **剪枝自然邻居**：沿某方向前进时，只保留一个前向邻居，其余兄弟节点都有等价的更短路径；
2. **识别强制邻居**：贴着障碍物前进时，那些"只有从这里绕才走得通"的格子；
3. **跳跃扫描**：沿方向一路扫描，遇到强制邻居、跳点或终点就停下来。

开阔地图实测：61×61 无障碍，A\* 扩展 3714 个节点，JPS 只扩展 **10 个**，耗时从 400 ms
降到 4 ms，而路径长度完全一致。

- **复杂度**：最坏仍为 `O(b^d)`，但典型地形下节点数可降一到两个数量级
- **优点**：无遮挡/稀疏障碍地形下无可匹敌，且不需要预处理
- **缺点**：依赖"允许穿过格子夹角"这一前提（详见下方说明），对 1 格宽缝隙极其敏感

> **关于本项目里的回退机制**
>
> 本项目全局采用**禁止穿墙角**的移动规则（斜走要求两侧正交格都可通行），而标准 JPS
> 的剪枝正确性建立在允许穿角之上。当地图出现 1 格宽缝隙（完美迷宫、随机障碍）时，
> 跳点搜索可能漏掉唯一通路。为此 `JumpPointSearchAlgorithm.find_path` 在跳点搜索无解时
> **自动回退到 A\***，并通过 `PathResult.fallback_used` 与 `message` 标注：
>
> - 结果永远合法且最优；
> - 稠密地图上的性能等同于 A\*（README 的基准表已经体现了这一点）；
> - 开阔地形下 JPS 的剪枝优势完整保留。

## 8. Theta\*

`ThetaStarAlgorithm` · 任意角度 · 路径最自然

Theta\* 在 A\* 的基础上放开"只能沿网格线走"的限制：扩展邻居时，如果**父节点的父节点**
与该邻居之间视线畅通（Bresenham 检测），就直接把邻居的父指针指到祖父节点，让路径斜着
穿过去。

```python
if line_of_sight(parent.parent.position, neighbor):   # 能直接连过去
    neighbor.parent = parent.parent                   # 跳过 parent，拉直
    neighbor.g_cost = parent.parent.g_cost + dist(parent.parent.position, neighbor)
else:
    neighbor.parent = parent                          # 维持原样（等价于 A*）
```

- **优点**：路径短且不含锯齿（实测 72.64 vs A\* 的 83.70，短 13%），适合机器人/车辆轨迹
- **缺点**：每次扩展都要做视线检测，实测比 A\* 慢 2 倍以上；产出的路径点不再是"逐格"的，
  校验时要用 `PathValidator.validate_any_angle`

## 横向对比

| 算法 | 最优性 | 相对速度 | 扩张节点 | 路径质量 | 推荐场景 |
| --- | --- | --- | --- | --- | --- |
| A\* | 加权最优 | 慢 | 多 | ★★★★★ | 通用默认 |
| Dijkstra | 加权最优 | 慢 | 多 | ★★★★★ | 基准对照、多目标最短路 |
| BFS | 步数最优 | 快 | 多 | ★★★★☆ | 无权图、最少步数 |
| DFS | 无保证 | 快 | 中 | ★☆☆☆☆ | 迷宫求解 |
| 贪心 | 无保证 | 最快 | 极少 | ★★★☆☆ | 实时性优先 |
| 双向 BFS | 步数最优 | 较快 | 中 | ★★★★☆ | 大地图单次查询 |
| JPS | 加权最优 | 开阔图极快 | 极少 | ★★★★★ | 开阔地形、游戏地图 |
| Theta\* | 加权最优（任意角度） | 最慢 | 多 | ★★★★★+ | 需要自然轨迹 |

## 路径后处理

算法输出的是"逐格折线"，往往还能再压一压：

| 工具 | 位置 | 作用 |
| --- | --- | --- |
| `PathSmoother.smooth_path` | `smartnav/planning.py` | 贪心视线拉直：能直连的中间点全部删掉，节点数常降到个位数 |
| `PathOptimizer` | `smartnav/planning.py` | 提供 `smooth`（拉直）与 `spline`（Catmull-Rom 插值）两种模式 |
| `PathInterpolator` | `smartnav/planning.py` | 线性/贝塞尔插值，把折线变成稠密的连续轨迹点 |
| `MultiWaypointPlanner` | `smartnav/planning.py` | 多途经点排序：最近邻构造 + 2-opt 迭代，逼近 TSP 最优 |
| `RouteOptimizer` | `smartnav/planning.py` | 直接对途经点坐标做 2-opt 排序（不查路网距离，更快但更粗） |

拉直后的路径要用 `PathValidator.validate_any_angle()` 校验，它沿线段做 Bresenham 视线
检测，确保没有穿墙——与 Theta\* 用的是同一套 `GridMap.has_line_of_sight`，判定标准唯一。
